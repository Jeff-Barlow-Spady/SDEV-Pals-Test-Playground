One-Time Setup in Visual Studio 2026

  1. Create an Empty Solution named SDEV2301Lab2Practice.
  2. Add a Class Library project targeting .NET 10. Name it OopPractice.
  3. Add an xUnit Test Project targeting .NET 10. Name it OopPractice.Tests.
  4. In OopPractice.Tests, add a project reference to OopPractice.
  5. Delete the automatically generated Class1.cs and UnitTest1.cs files.
  6. Create a Models folder inside OopPractice.

Visual Studio may create either a .slnx or .sln solution file. Either is acceptable. No additional assertion package is required; use the built-in xUnit Assert methods.

Use This TDD Cycle for Every Behaviour

  1. RED: Write one test for one behaviour.
  2. Run the test and confirm that it fails for the reason you expected—not because of an unrelated syntax or setup error.
  3. GREEN: Write the minimum production code required to pass that test.
  4. Use Run All Tests and confirm that all tests pass.
  5. REFACTOR: Improve names or remove duplication without changing behaviour.
  6. Run all tests again, then repeat the cycle for the next behaviour.
Do not write all the tests first and then write the entire class. Work in small test-code cycles. A useful test must fail before the required behaviour is implemented.

Testing conventions

  • Organize each test using Arrange–Act–Assert.
  • Name tests using Member_Scenario_ExpectedResult.
  • Use [Fact] for one case and [Theory] with [InlineData] for repeated cases.
  • Use Assert.Throws<TException>(...) to test exceptions.
  • Use a precision or range assertion when comparing calculated double values.

Core Practice A: Book Complete before Lab 2

Create these new files:

  • Production file: OopPractice/Models/Book.cs
  • Test file: OopPractice.Tests/BookTests.cs

Required behaviour

  • Title is a required string. Blank or whitespace input throws ArgumentException.
  • Pages is an int greater than zero. An invalid value throws ArgumentOutOfRangeException.
  • Subtitle is optional and must be declared as string?.
  • The constructor receives all required values and optionally receives a subtitle.
  • DisplayTitle() returns "Title: Subtitle" when a subtitle is present; otherwise, it returns only the title.

Write and pass these tests one at a time

  1. Constructor_ValidValues_SetsProperties
  2. Constructor_BlankTitle_ThrowsArgumentException
  3. Constructor_NonPositivePages_ThrowsArgumentOutOfRangeException — use a [Theory].
  4. DisplayTitle_SubtitleProvided_IncludesSubtitle
  5. DisplayTitle_SubtitleMissing_ReturnsTitleOnly
Nullable-types reminder: use string? because the subtitle may be absent. Handle the missing value deliberately—for example, by checking it or using ??. Do not silence nullable warnings with ! merely to make the warning disappear.

Core Practice B: BankAccount Complete before Lab 2

Create these new files:

  • Production file: OopPractice/Models/BankAccount.cs
  • Test file: OopPractice.Tests/BankAccountTests.cs

Required behaviour

  • AccountNumber is required. Blank or whitespace input throws ArgumentException.
  • Balance is a decimal that can be changed only by the class.
  • The opening balance defaults to 0m and cannot be negative.
  • Deposit(decimal amount) accepts only values greater than zero.
  • Withdraw(decimal amount) accepts only values greater than zero.
  • Withdrawing more than the balance throws InvalidOperationException and leaves the balance unchanged.

Write and pass these tests one at a time

  1. Constructor_NoOpeningBalance_SetsBalanceToZero
  2. Constructor_NegativeOpeningBalance_ThrowsArgumentOutOfRangeException
  3. Deposit_PositiveAmount_IncreasesBalance
  4. Deposit_NonPositiveAmount_ThrowsArgumentOutOfRangeException — use a [Theory].
  5. Withdraw_AmountWithinBalance_DecreasesBalance
  6. Withdraw_AmountExceedsBalance_ThrowsInvalidOperationException
  7. Withdraw_AmountExceedsBalance_LeavesBalanceUnchanged

Create these new files:

Required behaviour

  • Length and Width are double values greater than zero.
  • Invalid dimensions throw ArgumentOutOfRangeException.

Challenge Practice: Playlist Composition Multi-class design

Create these new files:

  • Production files: OopPractice/Models/Song.cs and OopPractice/Models/Playlist.cs
  • Test files: OopPractice.Tests/SongTests.cs and OopPractice.Tests/PlaylistTests.cs

Required behaviour

  • Song requires a nonblank Title and Artist.
  • LengthInSeconds must be greater than zero.
  • Playlist owns a private collection of songs.
  • SongCount exposes the number of songs without allowing outside code to replace the collection.
  • AddSong(Song song) rejects null with ArgumentNullException.
  • TotalLengthInSeconds() returns the combined length of all songs and returns zero for an empty playlist.

Suggested tests

  • AddSong_ValidSong_IncreasesSongCount
  • AddSong_NullSong_ThrowsArgumentNullException
  • TotalLengthInSeconds_EmptyPlaylist_ReturnsZero
  • TotalLengthInSeconds_MultipleSongs_ReturnsCombinedLength

Responsible Use of AI

AI tools may support this take-home practice, but they should not replace your thinking or your TDD cycle.

  • Design and write the next test yourself before asking for help.
  • Use AI for explanations, hints, troubleshooting, or feedback on a small piece of code.
  • Do not ask AI to generate the entire exercise and all tests in one response.
  • Run every test yourself and verify that it fails and passes for the intended reasons.
  • You must be able to explain every test, assertion, exception, and production-code change.
